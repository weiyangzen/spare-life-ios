# Stage 2 Blueprint

## 1. 说明

本文件是 `Spare Life iOS Stage 2` 的唯一权威需求源。

`Docs/Stage2_Blueprint_0328_Checklist.md` 只是从本文件生成的执行镜像，不是第二需求源。

Stage 2 默认围绕 5 个底部导航页面展开：

- 闲人
- 闲聊
- 赚闲能
- 消息
- 我的

## 2. 全局约束

### 2.1 瀑布流与卡片

- iPad 横屏使用 `5` 列卡片瀑布流。
- iPhone 与 iPad 竖屏使用 `2` 列卡片瀑布流。
- 所有主卡片统一使用 `圆角`。
- 所有主卡片统一使用 `高度:宽度 = 8:5`。
- 卡片之间的间距与卡片距离屏幕边缘的内边距统一为 `8px`。
- 共享的瀑布流与卡片样式必须先沉淀为全局可复用实现，后续 5 个页面复用，不允许各页面各写一套。

### 2.2 全局导航

- 全局 bottom nav 点击后必须可以稳定切换到正确页面。
- 切换体验需要体面，不能出现点击无反应、停留在第一页、误触透传、布局跳闪。
- 由于 5 个按键的 bottom nav bar 会遮挡实际功能区，需要给出优雅的 UI 解决方案。
- 解决方案必须同时兼顾：
  - iPhone
  - iPad
  - 键盘弹起
  - 滚动内容区
  - 卡片瀑布流列表
- 不允许通过简单压缩内容高度或让底部真实功能长期被遮挡来“假装解决”。

## 3. 页面要求

### 3.1 闲人

- 必须能够全量获取 `1200 topic shards`。
- `topic shards` 里暂时没有完整群名、人名时，显示逻辑化简为最后四位。
- `topic` 需要在后端对 `raw text` 调用 `summary` 增加可读性。
  这一步允许依赖远程机器配合落地。
- `topic / topic shard` 只显示“人说了什么”，用 IM 方式渲染每条信息。
- 每条信息最少要包含：
  - id
  - 时间
  - 内容
- 不允许继续把原始 txt 直接整段罗列给用户。

### 3.2 闲聊

- `assets` 里的大师必须能刷出卡片。
- 当前已有 `8` 位大师资源，Stage 2 至少完整呈现这批。
- 跟大师对话时需要全量加载 context。
- 闲聊聊天框需要接入 ClawDB 服务器的 `ASR` 接口，实现语音识别输入。
- 对话请求通过提供的 `k2p5` 模型落地：
  - 假设当前是一个小说场景
  - 角色说出的话必须符合 context
  - 台词必须合情合理

### 3.3 赚闲能

- 页面上方有分类页面：
  - 跑腿
  - 嘴替
  - 搭子
  - 两性
  - 求职招聘
  - 投融资
  - 闲置
- 每个分类页面放 `10` 个 Mock 卡片，简介对面的需求。
- 点击卡片后可以看到聊天框。
- 针对每一类，后续需要能对接 `../Social_Masks_EvoHack/` 自动落地合适的 `社交面具 Talk`。
- `Mock` 数据放在本地存储 / assets。

### 3.4 消息

- `Mock 10` 个人的卡片。
- 点击进入后是类 IM 的聊天界面。
- 它和“闲聊”不同：
  - 这里可以为对方选中 `真人 / 分身` 模式
  - 需要有可切换的开关
- `Mock` 数据放在本地存储 / assets。

### 3.5 我的

需要呈现的数据分四组：

- 闲人相关
  - OpenClaw 上的渠道数
  - 话题数
  - 独立 id 数
  - 被 Mention 次数
  - 以上数据从后端 ClawDB 获取
- 闲聊相关
  - 大师交互人数
  - 大师交互次数
- 赚闲能相关
  - 分类页面的交互人数
  - 分类页面的交互次数
  - 个人赚能风格描述
  - 以上可以 mock
- 消息页面相关
  - 本人真人互动数
  - 本人分身对外互动数
  - 对外真人互动数
  - 对外和其他分身互动数
  - 以上可以 mock
